# v0.3.0-cache-tiered

本版為 [mkyt/qwen3-27b-5090](https://github.com/mkyt/qwen3-27b-5090) 的 fork（分支 `tiered-kv-cache`）發行版，針對 RTX 5090 上的 Qwen3.8-27B 推論引擎。

## 1. 摘要

本版加入**分層 KV 快取**（VRAM → RAM → SSD）。GPU 上的 KV 快取池逐出的前綴 checkpoint 會先保存到主機 RAM，閒置後再寫入 SSD；之後同一前綴的請求可直接還原，不必重新計算。

- 推理 Slot 上限 8 個（預設 4 個）。
- KV 快取池預設 512K token（`KV_POOL_TOKENS=524288`）。
- KV 快取格式預設 NVFP4（`KV_DTYPE=nvfp4`）。
- 推論核心（CUDA kernels）未改動，不影響 RTX 5090 的吐字速度。

## 2. 新功能

- **分層 KV 快取**
  - VRAM 逐出到 RAM：快取池滿時，被逐出的 checkpoint 寫入 RAM（`SPILL_RAM_GIB`）。
  - RAM 到 SSD：在 RAM 停留超過 `SPILL_RAM_RETENTION_S` 秒且伺服器閒置時，寫入 SSD。
  - SSD 清理：超過 `SPILL_TTL_DAYS`（7 天）未被重用的檔案會刪除；SSD 層受 `SPILL_SSD_GIB` 上限約束，並保留 `SPILL_SSD_MIN_FREE_GIB` 的磁碟可用空間。
- **閒置時備份 VRAM 到 RAM**：閒置 `VRAM_BACKUP_IDLE_S` 秒後，VRAM 中的 checkpoint 複製一份到 RAM，VRAM 副本保留。
- **加速選項（預設關閉）**
  - `SPILL_PINNED_GIB`：pinned 主機記憶體池。
  - `SPILL_ASYNC_IO`：checkpoint 在獨立 CUDA stream 上複製，不阻塞 GPU 與引擎執行緒。
  - `SPILL_ASYNC_PROMOTE`：前綴命中 RAM 或 SSD 上的 checkpoint 時，請求在 `restoring` 狀態等待背景載入；只有載入明顯快於重新計算時才會載入。
- **.q27kv 檔案的模型指紋**：SSD 上的快取檔帶有模型指紋，與目前權重不符者不會被使用。
- **狀態頁 `/ui`**：分為「推理 Slot」、「分層快取」、「部署與硬體」三區，並顯示 tok/s。
- **啟動設定建議**：`tools/recommend_config.py` 依本機的 GPU、RAM 與磁碟算出建議值（預設只讀取，`--write .env` 才寫入）。
- **原生 Windows 套件**：zip 內含托盤程式、`start.cmd` 與 `update.cmd`。
- **Docker 映像**：由本 checkout 建置。
- **所有參數可在啟動時覆寫**：以環境變數設定，或在 Windows 的 `settings.ini` 的 `[env]` 區段設定。

## 3. 預設值

| 變數 | 預設值 | 說明 |
|---|---|---|
| `KV_POOL_TOKENS` | 524288 | KV 快取池大小（512K token） |
| `MAX_SEQS` | 4 | 同時執行的請求數（上限 8） |
| `KV_DTYPE` | nvfp4 | KV 快取格式 |
| `WEIGHTS` | gdnfp4 | 權重設定檔 |
| `PORT` | 46320 | API 與 Web UI 埠 |
| `SPILL_RAM_GIB` | 32 | RAM 分層上限（GiB） |
| `SPILL_RAM_RETENTION_S` | 3600 | RAM 停留秒數，之後寫入 SSD |
| `SPILL_SSD_GIB` | 100 | SSD 分層上限（GiB） |
| `SPILL_SSD_MIN_FREE_GIB` | 10 | SSD 所在磁碟保留的最小可用空間（GiB） |
| `SPILL_TTL_DAYS` | 7 | 未被重用的 SSD 檔案保留天數 |
| `VRAM_BACKUP_IDLE_S` | 60 | 閒置多久後備份 VRAM 到 RAM（秒） |
| `SPILL_PINNED_GIB` | 0 | pinned 記憶體池（關閉） |
| `SPILL_ASYNC_IO` | 0 | 非同步 I/O（關閉） |
| `SPILL_ASYNC_PROMOTE` | 0 | 非同步還原（關閉） |

SSD 層的目錄：

- Windows：`%LOCALAPPDATA%\qwen3-27b-5090\kvcache`
- Docker：`/cache/kv`（具名磁碟區 `kvcache`）

## 4. 實機測試

測試環境：RTX 5090、Windows 原生、權重 gdnfp4。

**正確性**：7/7 情境 PASS，每段輸出與關閉快取的基準完全一致。

**還原延遲**（短前綴）：RAM 還原 2 ms，SSD 還原 169 ms。

**256K context 基準**（預設 對 加速選項 `SPILL_PINNED_GIB=8`、`SPILL_ASYNC_IO=1`）：

| 項目 | 預設 | 加速選項 |
|---|---|---|
| VRAM 逐出到 RAM | 401 ms | 25 ms |
| RAM 升回 VRAM | 402 ms（12 GB/s） | 96 ms（52 GB/s） |
| 閒置備份 VRAM 到 RAM | 583 ms | 87 ms |
| SSD 升回 VRAM | 1684 ms | 1186 ms |

寫出 SSD 約 2.2 秒。作為對照，重新計算 256K 的 prefill 需要 56 秒。

## 5. 建議設定

加速選項預設關閉。在 GPU 上通過 `scripts/tiered_cache_test.py` 之後，可以啟用：

- Windows：在 `settings.ini` 加入

  ```ini
  [env]
  SPILL_PINNED_GIB=8
  SPILL_ASYNC_IO=1
  SPILL_ASYNC_PROMOTE=1
  ```

- Docker：在 compose 的 `serve` 服務的環境變數加入相同三項。

啟用後約使用 11 GB 的 pinned 主機 RAM。

## 6. 安裝 / 更新

**Windows**

- 下載 `qwen3-27b-5090-v0.3.0-cache-tiered-windows-x64.zip` 與 `.sha256`，先核對 SHA-256 再解壓。步驟見 `docs/deploy-windows.md`。
- 既有安裝：執行 `update.cmd`。

**Docker**

- 映像：`ghcr.io/weih97837-design/qwen3-27b-5090:0.3.0-cache-tiered`
- 或在本 checkout 本地建置：`docker compose up -d --build serve`（見 `docs/deploy-cli.md`）。

**埠**

- API 與 Web UI 使用 46320，狀態頁為 `http://127.0.0.1:46320/ui`。
- 請勿使用 8765。

## 7. 注意事項

- 需要 RTX 5090（SM120）與支援 CUDA 13 的驅動程式。
- SSD 快取檔綁定模型指紋；更換權重後，既有的 SSD 快取不會被使用。
- 埠 8765 不使用。
