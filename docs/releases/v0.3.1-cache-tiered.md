# v0.3.1-cache-tiered

v0.3.0-cache-tiered 之後的第一個改善版：提高多 agent 工作負載的前綴快取命中率、減少 RAM 與 SSD 的浪費，
並讓分層快取的參數可以直接在托盤與網頁設定。

## 新功能與改善

**命中率**
- 同時送出、開頭相同的請求可以共用快取：即使另一個請求已經開始計算，也會在共用處補一個存檔點，
  新請求等它算到那裡後直接沿用（修正「同時送出只命中 system prompt 那一段」的問題）。等不到時不再空等。
- 存檔點槽位加倍：`STATE_HOST_CACHE` 預設 4 → 8 GiB（約 42 個存檔點）。
- 存檔間隔縮短：`CHECKPOINT_INTERVAL` 預設 8192 → 4096，長對話中間有更多接續點。
- 存檔槽滿時，優先淘汰「同一段對話已有更深存檔點涵蓋」的存檔點；對話分岔點保留。
- 中途取消的請求（已開始生成）也會保留結尾存檔點。

**RAM / SSD 用量**
- `SPILL_RAM_GIB` 預設 32 → 64 GiB（上限，用多少佔多少）。
- 新設定 `SPILL_SSD_MIN_TOKENS`（預設 8192）：短於此長度的快取不寫入 SSD（重算很快，寫入只浪費空間與壽命）。
- 閒置備份更節制：只備份最可能被擠出 VRAM 的前 8 個存檔點（`VRAM_BACKUP_VICTIMS`），且備份最多佔 RAM 層的一半。

**VRAM**
- 改為設定「最少預留的 VRAM」：`VRAM_RESERVE_GIB`（預設 1.5 GiB，5090 上與舊版自動預算相同），移除 30.3 GiB 的硬上限。
  舊的 `VRAM_BUDGET_GIB` 只在直接以命令列啟動引擎時仍有效。

**設定介面**
- 分層快取的 11 個參數（RAM/SSD 大小、停留時間、保留天數、SSD 最小長度、閒置備份、加速選項、快取資料夾）
  可在托盤設定視窗（右欄「Tiered cache」）與 `/ui` 啟動設定直接修改，引擎重啟後生效。

**監控頁 `/ui`**
- 新增「Turn 2+ hit」（第 2 輪之後的命中率）與「Checkpoint slots」（存檔槽用量）。
- 分層快取區顯示各層的備份與逐出項目拆分。
- Log 中標示「≠」的請求代表開頭與之前的請求在中途不一致；引擎 log 會記錄不一致的位置與附近文字，方便找出 prompt 中會變動的內容。

## 給 agent 程式的建議

- 每個請求帶 `X-Agent-Id` header（或 OpenAI `user` 欄位）；本版尚未使用，下一版的 agent 公平淘汰會用到。
- system prompt 不放時間戳等會變的內容；工具清單順序固定；歷史訊息只追加不改寫；模型回覆原樣放回。

## 安裝 / 更新

- 既有安裝：執行 `update.cmd`。
- 退回上一版：`update.cmd -Tag v0.3.0-cache-tiered`。
- 新安裝：下載 `qwen3-27b-5090-v0.3.1-cache-tiered-windows-x64.zip` 與 `.sha256`，見 `docs/deploy-windows.md`。
- Docker：`ghcr.io/weih97837-design/qwen3-27b-5090:0.3.1-cache-tiered`。

## 注意事項

- 本版引擎改動已通過編譯與單元測試，GPU 正確性請以 `test.cmd`（分層快取 a–g 情境）確認。
- 推論核心（CUDA kernels）未改動。
